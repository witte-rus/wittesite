# Сайт Witte-rus — каталог оборудования для животноводства

Многостраничный сайт-каталог: 156 карточек изделий, 3 направления, 19 категорий (из них 4 — «подбор по запросу»), 40 подкатегорий, 221 страница. Фирменный стиль WITTE: логотип (свинья и курица) в `site/assets/img/brand/`, цвета #0B49B0 / #0A1E45 / #F4B63A, шрифты Unbounded (заголовки) и Manrope (текст, Google Fonts).

## Запуск на компьютере

Сайт вместе с кабинетом менеджера (нужен Python 3.9+):

```bash
pip3 install -r requirements.txt
```

```bash
python3 tools/dev_server.py
```

Откройте http://localhost:8080/ — сайт, http://localhost:8080/manager/ — кабинет менеджера (пароль для локальной проверки — `witte-dev`, меняется переменной `DEV_MANAGER_PASSWORD`). Локально заявки сохраняются в `data/requests/dev.sqlite`, письма не отправляются, а изменения оборудования записываются прямо в файлы проекта с пересборкой сайта.

Только статический сайт без кабинета: `python3 tools/server.py`.

> Если открыть `site/index.html` двойным щелчком (без сервера), ссылки и поиск работать не будут: сайт использует абсолютные адреса. Запускайте через `tools/server.py`.

## Пересборка после изменения данных

```bash
python3 tools/build.py
```

Скрипт генерирует все HTML-страницы, `sitemap.xml`, `robots.txt` и поисковый индекс. Предупреждения (несуществующие фото, ссылки на неизвестные изделия, категории) выводятся в консоль.

Проверка ссылок на работающем сервере:

```bash
python3 tools/check_links.py
```

Повторное извлечение фотографий из исходных каталогов (нужны `pip3 install pymupdf pillow python-pptx`):

```bash
python3 tools/extract_images.py ~/Downloads/witte
```

## Где что лежит

| Путь | Содержимое |
|---|---|

| `data/products/*.json` | Карточки изделий (кормление, поение, климат и обогрев, полы и содержание). Серии (полы, ПВХ-панели, ниппельные поилки) разворачиваются в отдельные страницы каждой модели |
| `data/company.json` | Карточка предприятия: реквизиты, телефон, часы работы, условия монтажа |
| `data/products/manager.json` | Оборудование, добавленное через кабинет менеджера (создаётся автоматически) |
| `backend/app.py` | Серверная часть: приём заявок, отправка на почту, API кабинета менеджера |
| `site/manager/`, `site/assets/js/manager.js` | Кабинет менеджера |
| `tools/dev_server.py` | Локальный запуск сайта с кабинетом |
| `data/documents.json` | Перечень документов для скачивания |
| `data/source-notes.md` | Сырые выписки из исходных каталогов (перевод, таблицы, номера страниц) |
| `tools/build.py` | Генератор сайта |
| `tools/server.py` | Локальный сервер + приём заявок |
| `tools/extract_images.py` | Извлечение фото изделий из PDF/PPTX (координаты кадров) |
| `tools/check_links.py` | Проверка битых ссылок и изображений |
| `site/` | Готовый сайт: страницы, `assets/` (CSS, JS, фото), `docs/` (каталоги PDF/PPTX; изображения в PDF пересжаты до 110–220 dpi, каждый файл не более 12 МБ) |
| `STRUCTURE.md` | Реализованные разделы и категории |
| `MISSING_DATA.md` | Недостающие фото, характеристики и данные предприятия |

### Формат карточки изделия

```json
{
  "id": "fan-hyfb",                       // часть URL
  "name": "…", "model": "…", "summary": "…",
  "cats": ["pig-farming/ventilation/exhaust", "poultry/ventilation/exhaust"],  // первая — основная (URL и хлебные крошки)
  "img": ["hyfb-1"],                       // файлы site/assets/img/p/<имя>.jpg
  "description": "…", "purpose": "…", "features": ["…"], "kit": ["…"],
  "params": [["Параметр", "Значение"]],
  "tables": [{"title": "…", "cols": ["…"], "rows": [["…"]]}],
  "docs": [{"doc": "hy", "pages": "3–4"}],  // ссылка на PDF откроется на нужной странице
  "related": ["fan-hya"], "facets": {"Корпус": "Сталь"}, "airflow": [26000, 58000],
  "maker": "…", "missing": ["что не хватает — в карточке не выводится"]
}
```

Раздел «подбор по запросу» задаётся в `data/catalog.json` у категории полями `"on_request": true` и `"request_points": [...]`. Пока в его подразделах нет изделий, на странице раздела показывается форма подбора; как только менеджер добавит изделие, раздел становится обычным списком товаров.

`facets` формируют фильтры в списках, `airflow` — фильтр по производительности.

## Что реализовано

- Навигация: направление → категория → подкатегория → карточка; раскрывающееся мега-меню на компьютере, полноэкранное меню с аккордеоном на смартфоне; хлебные крошки.
- Общие карточки для нескольких направлений (например, вентиляторы — в свиноводстве и птицеводстве) без дублирования, с блоком «Применение».
- Карточки изделий: галерея с увеличением, описание, назначение, особенности, характеристики и таблицы исполнений, комплектация, документация со ссылкой на страницу PDF, сопутствующие изделия, кнопка «Запросить цену».
- Фильтры в списках (размер, группа животных, тип, корпус и т. п.), фильтр вентиляторов по производительности, поиск по разделу.
- Поиск по каталогу (название, модель, артикул, размеры).
- Форма запроса КП с проверкой полей, подстановкой выбранного изделия; заявка сохраняется в базе и отправляется на почту witte-rus@mail.ru.
- Кабинет менеджера: заявки и редактирование каталога оборудования.
- SEO: уникальные title/description, canonical, Open Graph, микроразметка (BreadcrumbList, Product, ItemList, Organization), человекочитаемые URL, `sitemap.xml`, `robots.txt`, страница 404.
- Адаптивная вёрстка (проверено на 375 px и 1440 px), без горизонтальной прокрутки.

## Кабинет менеджера

Адрес: `/manager/` (закрыт от поисковиков, вход по паролю).

- **Заявки** — все запросы КП с сайта: статус (новая, в работе, КП отправлено, закрыта, спам), заметка менеджера, поиск, выгрузка в Excel (CSV).
- **Оборудование** — добавление, изменение и удаление изделий со всеми полями карточки: название, модель, разделы каталога, фото (загрузка, порядок, удаление), описание, назначение, исполнения, особенности, комплектация, параметры, таблицы, фильтры, производительность, документы, сопутствующие изделия. После сохранения изменения записываются в репозиторий GitHub, и Layero пересобирает сайт (1–3 минуты). Модели серий (пластиковые полы, ПВХ-панели, ниппельные поилки) правятся в файлах `data/products/*.json`.
- **Подключения** — какие сервисы настроены.

## Публикация на Layero (сайт + кабинет + почта)

`layero.json` описывает полноэкранную сборку: статическая часть (`site/`, собирается `python3 tools/build.py`) и серверная часть (`backend/app.py`, FastAPI) по адресу `/api`.

В Layero: **Project → Environment Variables** задайте:

| Переменная | Значение |
|---|---|
| `MANAGER_PASSWORD` | пароль входа в кабинет (длинный, не короче 12 символов) |
| `SECRET_KEY` | случайная строка из 40+ символов (подпись сессий) |
| `SMTP_USER` | `witte-rus@mail.ru` |
| `SMTP_PASSWORD` | **пароль для внешних приложений** mail.ru (не основной пароль): Почта Mail.ru → Настройки → Безопасность → Пароли для внешних приложений |
| `MAIL_TO` | куда приходят заявки, по умолчанию `witte-rus@mail.ru` |
| `GITHUB_TOKEN` | fine-grained токен GitHub с доступом только к `witte-rus/wittesite`, право **Contents: Read and write** |

**База данных.** Чтобы заявки хранились в кабинете, подключите к проекту базу PostgreSQL в Layero (раздел Databases): общая база входит в тариф Pro, выделенная — отдельно. Layero сам задаёт переменную `LAYERO_DATABASE_URL`. Без базы заявки всё равно приходят на почту, но в кабинете их не видно.

## Перед публикацией

1. Указать домен в `data/company.json` (`site_url`) и пересобрать сайт.
2. Заменить фото и данные по списку из `MISSING_DATA.md`.
